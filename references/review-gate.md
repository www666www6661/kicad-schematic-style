# 预配置独立检查入口

主 agent 使用 `scripts/review_gate.py`，不临时重写审查提示词。固定职责在 `reviewer-prompt.md`，输出结构在 `review-report.schema.json`；它们由脚本装入当前版本的审查任务。

## 何时触发

| 节点 | 操作 |
|---|---|
| 新建/整体整理的全图首次集成，绘制者已完成局部自查、主 agent 已完成全局组合自查 | `run --stage layout`，独立核对构图、紧凑度与遗漏；不接手作者尚未完成的常规排版 |
| 有限收紧、图幅选择及修复完成，准备交付 | `run --stage final`；若首次检查时已到最终版本，从 final 开始 |
| 检查要求修改 | 主 agent 集中修复一批并验证，再以 `--previous-review <上轮目录>` 触发当前版本复查；问题逐项闭环 |
| 既有图局部修改 | 小字段微调按原流程自查；需要独立复核时用 `--scope local --affected-ref R12`，可重复指定受影响位号 |

这里是明确节点上的调用入口，不是后台监听器，也不触发编辑器刷新。检查脚本只读工程，主 agent 负责修图、验证和调度下一轮。检查与修复按下面的闭环推进。

局部首轮构造和交接按[布局流程](functional-layout.md#首次生成从端点向外安排)执行。作者自查可在同次原生导出中批量完成，不为每个局部新增独立 gate。独立检查仍覆盖当前图面，不能因作者声称“初次已紧凑”免检；自查记录本身也不是图面质量证据。遇到同一生成默认在多处复发，修复该生成策略及受影响局部后再提交，不逐个空跨度启动整页 battle。

## 默认的一次调用

需要 Python、PyMuPDF、目标版本 `kicad-cli` 和已配置可运行的 Codex CLI。未指定 `--model` 时沿用用户的 CLI 模型配置，不固定模型、价格或供应商。`--requirements` 给原始功能需求和用户有效约束，不放主 agent 的自评、历史缺陷清单或聊天总结。

```powershell
$styleSkillRoot = 'C:\Users\wuji\.agents\skills\kicad-schematic-style'
python -B -X utf8 "$styleSkillRoot\scripts\review_gate.py" run 'C:\task\main.kicad_sch' --stage layout --requirements 'C:\task\requirements.md' --kicad-cli 'D:\app\KiCad\10.0\bin\kicad-cli.exe'
```

默认新建临时输出目录并立即打印其路径。也可用 `--output` 指定尚不存在的目录。调用会：

1. 复用 `schematic_check` 采集当前源、依赖、原生 XML/ERC/PDF；用冻结源逐页跑几何探针。
2. 装入当前需求、绘图规则、冻结源、PDF 和整页/细节图片；复查时另外冻结指定上一轮的审查者原始报告，供独立观察后逐项核对。不装入作者修复自评、聊天记录或校准案例。
3. 用固定提示词启动新的 `codex exec --ephemeral --sandbox read-only`，不 resume/fork 作者会话；本进程关闭已配置 MCP、插件和自动 skill，并清除父会话 ID，不修改用户配置文件或认证。首轮看图后再看探针候选。
4. 收取结构化报告，核对受审版本、输入哈希、图面覆盖声明和现场是否变化，生成 `gate-result.json`。日志和原始响应留在本次输出目录。

默认单次审查超时 900 秒，可用 `--timeout` 调整；超时会结束本次启动的进程树并保留未验证状态。宿主调度此命令时使用可轮询的后台会话，不阻塞用户沟通。失败不自动重试、不切模型；排除运行问题后可另开一次审查。

## 检查与修复闭环

1. **检查 agent 出具问题。** 首轮从当前图面独立形成 `findings` 与 `space_checks`。问题带稳定 ID、对象、证据和可行改向；主 agent 不替检查者改结论。
2. **主 agent 修一批。** 核实问题后调整字段、局部回路或全局组合，回灌在用生成器；按验证细则检查实际差异。遇到与电气或阅读约束冲突的建议，保留当前安全版本及具体依据，不能为了通过检查盲改。图面检查不替代电气/身份验证。
3. **检查 agent 看新版本。** 使用新的输出目录，同一阶段、范围调用入口并带 `--previous-review`。默认每轮都是新上下文，先看当前整图与局部，再读取包内上一轮报告，输出每个旧问题的 `rechecks`：已解决、仍存在、不再适用或未验证。已解决的依据是新图面，不能引用主 agent 的“已修复”。同时检查受影响邻组和全局组合，记录新问题。
4. **按结果推进。** 还有明确问题就回到第 2 步；layout 通过后进入最终收紧/图幅和 final 检查，final 通过且适用的电气检查完成才结束。当前轮存在的所有问题保留在 `findings` 中，旧问题不能因换了轮次而消失。每轮目录保存独立快照和原始回报，不覆盖上一轮。

复查调用示例：

```powershell
python -B -X utf8 "$styleSkillRoot\scripts\review_gate.py" run 'C:\task\main.kicad_sch' --stage layout --requirements 'C:\task\requirements.md' --kicad-cli 'D:\app\KiCad\10.0\bin\kicad-cli.exe' --previous-review 'C:\task\checks\layout-01' --output 'C:\task\checks\layout-02'
```

`--previous-review` 同样适用于 `prepare` 加宿主子 agent 的方式；脚本核对上一轮来源、范围和冻结证据，不把本轮修改导致的旧现场哈希变化当作历史证据损坏。检查者的历史报告只用于逐项复查，不能先读历史再声称首次独立观察。层级/范围改变时重新做该范围首审，在已有工作记录中保留未完事项。

默认每个阶段最多做三批修复与复查；如果提前通过就停止。连续两轮同一问题没有实质进展、在两个排法间反复，或修复需改变未授权的电气设计时，停止自动尝试并报告具体争议/剩余项。轮数用完不构成验收通过，必要检查缺失也不能降级为建议以求通过。该上限限制执行成本，不是绘图质量标准；用户要求继续时可继续。工具失败先处理运行原因，不在原图未变时反复抽取新的审查结果。有限布局流程负责单批修改，本节负责检查驱动的多批闭环。

## 电气基线和图幅证据

- 既有图整理用 `--before <修改前的快照目录>` 自动附带全图身份/网表/ERC 比较。无基线时明确未验证，不能凭视觉结论声称电气等价。
- 最终图幅需要较小候选证据时，先按布局细则做一次候选并用 `schematic_check.py snapshot ... --pdf` 留下快照，再通过 `--paper-candidate <候选快照目录>` 交入。脚本装入候选源、原生图面、逐源探针及比较事实，探针随 `page_evidence.json` 索引并冻结；复核者在形成当前图独立意见后再查看，结合源核对 PDF 裁掉的对象。候选是否经过有效组合由复核者判断，越界数量和“缩小失败”文字不代替试排。
- 候选使用独立目录中的完整工程副本，保留主文件名、层级相对路径和项目依赖。仅给主图改名也可能改变原生导出的 `Sheetfile` 属性，使内容比较不通过；先修正副本组织再采集，不删属性差异来凑等价。
- 用户明确指定纸张才用 `--fixed-paper`。局部修改和已到 A5 的常规任务可有图幅例外，仍要看实际边界。没有候选证据且不属于例外时，final 的图幅结论保持未验证。
- 编号冻结源用于读证据，不是可重新导出的项目副本；不要对它运行生成器或拿它冒充完整层级工程。

## 无外部 CLI 时的固定交接

不需要主 agent 自己写提示词。把上例 `run` 换成 `prepare`，读取输出目录中的 `dispatch.json`，将其 `task_name`、`fork_turns="none"`、`message` 原样交给宿主的 `spawn_agent`。不补充作者解释或预期答案。子 agent 只返回符合 schema 的 JSON，主 agent 原样保存到临时响应文件，再调用：

```powershell
python -B -X utf8 "$styleSkillRoot\scripts\review_gate.py" finalize '<本次输出目录>' --report '<子agent原始JSON响应文件>' --reviewer-id '<实际子agent ID>'
```

已准备的包也可以用 `review_gate.py review <输出目录>` 启动外部 CLI。没有可用的独立执行器时保留未验证，不让主 agent 代填审查者的通过结论。原生子 agent 的新上下文由宿主调用保证，脚本不能替宿主证明它没有继承历史。

## 结果怎么用

| 状态 / 退出码 | 含义与后续 |
|---|---|
| `AWAITING_REVIEW` / 0 | prepare 成功，尚无人工图面结论 |
| `REVIEW_ACCEPTED` / 0 | 本阶段、本范围的视觉复核接受；继续读取电气比较和未验证项，不是整项工程认证 |
| `CHANGES_REQUESTED` / 1 | 复核指出需处理的问题；主 agent 按具体证据修复 |
| `UNVERIFIED` / 2 | 响应缺失/运行失败、覆盖不足或必要证据不足；已有问题仍保留在报告内 |
| `STALE` / 3 | 当前源、需求、规范、依赖或工具已变化；重采当前版本，不复用旧通过结论 |

每次读取结果中的 `stage`、`scope` 和 `affected_refs`。整页 PNG 与四个细节区域的查看记录是审查者声明，脚本能查缺项，不能证明模型真看准了。报告声明读到包外任务材料时按未验证处理。共享文件系统及 CLI 全局指令仍可能提供其他信息，输入包和新进程都不等于完全的读取权限隔离。规则文件更新也会使进行中的审查过期。

同时读取 `review.assessments`、`findings` 和 `rechecks`，不要只看顶层状态。`UNVERIFIED` 可以与已确认的紧凑度失败并存；工具覆盖缺口不会撤销仍开放的图面问题。独立复核尚在运行、图幅未验证或仍有开放问题时，文件与进度说明使用“当前草稿/待复核”；到停止条件可交付该状态的成果和剩余项，不能提前写“最终图幅已选定/验收完成”。

报告 schema v2 增加 `space_checks`：整图检查每页都有组内与组间观察，局部检查覆盖实际修改区的组内观察。每条指明位号/节点/层级名、空白位置，以及需调整、可保留或未验证的理由；脚本拒绝缺层级覆盖或“尚需调整却宣称紧凑度通过”的响应。它检查报告完整性与自洽性，不能验证保留理由是否看准。图幅例外不豁免这些观察，图幅证据缺失也不替代当前图的紧凑度判断。旧 schema 报告保留为历史证据，不补字段冒充重新审查。

多页整体检查另外要求全工程的 `pagination` 结论和至少一条 `across_sheets` 观察，检查内容组合与分页依据。即使各页均为 A5、纸张固定或单页内部都紧，这一层也不能省略。只有局部范围或确实只有一页时，分页结论可不适用；新建图不能把自行决定的层级当成用户固定条件。

无图幅例外的 final 整体审查若要通过 `paper`，每个当前页面还需 `paper_trial` 观察，锚点标明候选对应的页面/核心，说明试排充分性及实际阻碍。未处理的候选排版问题用 `change_needed` 并对应同页 `paper` finding，证据不足用 `unverified`；充分试排后保留或采用图幅才用 `retained`。脚本检查这些记录及候选图面/电气证据的完整性，不用其代替几何判断，也不为旧审查补写记录。

同一 schema 的 `rechecks` 在首审为空，复查时完整对应上一轮的 `findings` ID。每个不通过的维度都需有同类别 finding，不能只留一句失败自评。仍存在的问题需继续列在当前 `findings` 中并使对应维度不通过；无法验证的旧问题也保留原 ID/类别并说明不确定处，阻止接受。组内/组间需改的空间记录要有同页的紧凑度 finding，跨页需改记录对应分页 finding，以便进入下一轮追踪。脚本不判断两种布局谁更好，也不替主 agent 自动选择修法。
