# 局部绘制者的固定交接

主 agent 派发局部绘制时，让执行者先读取本文件，并提供以下实际输入。执行者自己绘制并自查，独立审查仍走 `review_gate.py`。这不是新审查关卡，也不要求每个小模块都派一个 agent。

## 派发输入

- skill 根路径、原始功能需求、本次局部的成员与已核实连接；未决电气项明确列出。
- 独占可写的片段/生成模块/工作副本，以及实际库、复用 helper 和调用方式；共享主图由主 agent 写。
- 服务对象、阅读链、外部端口及相邻核心；只给确有依据的几何限制，不预分宽松的纸面槽位。
- 交接输出位置；端口发生变化时的协调对象。

提供实际原始材料路径即可，不复制整段聊天历史。缺少决定电气正确性的输入先核实，非依赖部分可继续；不自行补猜引脚或参数。

## 执行者指令

你负责交付一个**内部已经构图、自查完成的局部电路**。主 agent 负责全局邻接和整页组合，后续独立 reviewer 负责查漏。

读取本 skill 的 `drawing-conventions.md`、`functional-layout.md` 和适用的 `editing-and-validation.md`。新建局部另读 [authoring-tools.md](authoring-tools.md)，优先使用已覆盖操作，不临时重写基础坐标/序列化 helper。按“首次生成：从端点向外安排”构造：先形成主器件、关键支持和反馈，再安排对外接口；用真实端点推导位置，字段参与首轮放置。已有 helper 若默认留长线、固定双行字段或大节距，在可写入口修正或向共享 helper 负责人提出具体修改，不把这些默认带进全部实例。

重复局部先用当前真实库和字段确认代表画法，再展开；原生预览可以合并导出。交接前完成有限局部检查，沿实际器件跟读功能，处理同一结构原因造成的空跨度及字段问题。把有争议的净空和确实受阻的位置说清楚，不编写“已紧凑”的固定结论，不用删件、缩字或割裂局部连接换面积。

在指定工作副本中生成或修改，按实际差异核对连接/身份及当前原生图面。只有局部范围时不运行全图独立 gate、不选最终纸张。保留显式完整子组和真实端口，便于主 agent 平移或提出有针对性的改形；局部自查不能宣称全图合格。

## 一次交接的内容

沿用已有消息或工作记录，先标明状态：`可集成`、`受阻` 或 `未完成`。`可集成` 表示本次适用的有限局部检查已完成，没有明确未处理的局部候选；`受阻` 指有具体依赖/约束阻碍；检查漏项或已发现但尚未处理的候选属于 `未完成`。这些是作者交接状态，不是独立验收结论。

简要返回：

1. 修改文件/调用入口、成员与真实端口；仍可调整的边或子组。
2. 已查看的当前原生预览位置、对应源版本，以及位号/节点组成的功能阅读链。
3. 实际完成的连接/身份检查、代表画法与差异检查。
4. 对照布局细则的四类局部余量，各写一句带实际对象的观察和处理结果：相邻端点、支持/返回回路、并联母线、字段与内部空白。已发现的候选写处理结果或具体阻碍；无候选写所看的对象与保留理由，不适用则说明。只完成字段碰撞检查时，其余项写未完成，不用“已紧凑”概括。

四项可合并在一次交接中，无需逐器件打分或另建完成报告。尚未完成自查的片段可用于临时接口验证。主 agent 不把这份作者交接作为独立检查者的通过依据。
